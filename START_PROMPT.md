# myVDKmap — «Мой дом. Владивосток»: промпт для старта разработки (savvy-flow)

## Как начать

1. Создайте пустую папку `myVDKmap` и положите в неё этот файл и папку `inputs/` с подготовленными данными (пути внутри `inputs/` — те, по которым файлы должны лежать в проекте):
   ```
   inputs/data/vladivostok_seed.json
   inputs/data/osm-buildings.json
   inputs/data/osm-addresses.json
   inputs/data/osm-address-points.json
   inputs/data/osm-complex-buildings.json
   inputs/public/geo/districts.geojson
   inputs/public/geo/complexes.json
   inputs/public/demo/pothole.svg
   inputs/lib/fixtures/bills.ts
   inputs/lib/fixtures/documents.ts
   inputs/scripts/fetch-geo.mjs
   inputs/scripts/fetch-buildings.mjs
   inputs/scripts/fetch-complex-buildings.mjs
   ```
2. Создайте `.env` с ключом 2GIS: `NEXT_PUBLIC_2GIS_KEY=...` (ключ не коммитится и не пишется в `.env.example`).
3. Откройте папку `myVDKmap` в Claude Code и выполните:
   ```
   /savvy-flow Сделай проект myVDKmap — сервис «Мой дом. Владивосток» — строго по START_PROMPT.md. Подготовленные данные лежат в inputs/ — перенеси их в проект на те же пути без изменений.
   ```

## 1. Продукт

**Интерактивная карта Владивостока: житель за три нажатия доходит от района до своего дома и получает «паспорт дома» — кто отвечает, что сломано, что будут ремонтировать — может сообщить о проблеме, разобрать квитанцию с помощью ИИ и вести личный кабинет.**

Проблема: жители не знают, кто отвечает за дом и двор, куда жаловаться, почему выросла квитанция и что меняется рядом. Информация разбросана и написана канцеляритом.

Навигация — как зум: **Город → Район → ЖК → Дом (паспорт) → Действие**. Состояние живёт в URL, ссылкой на дом можно поделиться.

## 2. Маршруты

| URL | Что |
|---|---|
| `/` | Город: карта на весь экран, панель города |
| `/d/[district]` | Район: камера на район, паспорт района |
| `/d/[district]/c/[complex]` | ЖК: карточка ЖК со списком домов |
| `/house/[id]` | Паспорт дома. `?issue=<id>` — подсветить и прокрутить к проблеме. `id` вида `osm-<osmId>` создаёт паспорт лениво (6.3) |
| `/report` | Мастер «Сообщить о проблеме» (`?building=<id>` — адрес подставлен) |
| `/bill` | Разбор квитанции (`?building=<id>`) |
| `/changes` | «Что меняется в городе»: лента работ, поиск по улице, разбор своего документа. `?building=<id>` — работы дома первыми; `?work=<id>` — подсветить и прокрутить к работе |
| `/me` | Личный кабинет (вход и регистрация, если не вошёл) |

Все страницы — в группе `app/(map)/` с общим `layout.tsx` (`dynamic = "force-dynamic"`): **карта монтируется один раз и не перезагружается при навигации**; страницы рендерятся в панель (`/report`, `/bill`, `/changes`, `/me` — поверх карты).

API (`app/api/**`; ошибки всегда `{ error: "<по-русски>", details?: [{ path, message }] }`; тело ≤ 8 МБ):
- `GET /api/search?q=` — поиск (6.2).
- `GET|POST /api/issues`, `POST /api/issues/[id]/support` — жалобы и «Меня это тоже касается».
- `POST /api/ai/classify`, `POST /api/ai/bill`, `POST /api/ai/document`, `GET /api/ai/digest?district=`.
- `POST /api/auth/register`, `POST /api/auth/login`, `POST /api/auth/logout`, `GET|PATCH /api/auth/me`, `POST|DELETE /api/auth/esia/demo`.
- `GET|PUT /api/cabinet/data`, `GET /api/cabinet/houses?ids=`.

## 3. Данные

### 3.1 Подготовленные данные (`inputs/`, переносятся без изменений)
- `data/vladivostok_seed.json` — 5 районов (население, цвета), микрорайоны, реальные ЖК, справочник органов (`uk`, `city_admin`, `gzhi`, `capremont`, `rpn`, `pos`).
- `data/osm-buildings.json` — жилые дома OpenStreetMap с этажностью (где есть — год, материал, квартиры).
- `data/osm-complex-buildings.json` — все здания внутри контуров ЖК (у новостроек часто нет адреса или этажности).
- `data/osm-addresses.json` — все адреса по улицам (для привязки документов к домам).
- `data/osm-address-points.json` — `{ source, fetchedAt, columns: [osmId, street, number, lat, lng, floors], points }`: 23 717 адресных точек, 951 улица — чтобы поиск находил абсолютно любой адрес.
- `public/geo/districts.geojson` — границы районов из 2GIS (`source: "2gis"`), `properties: { id, name, color }`. Фрунзенский район — только городская часть, без полуострова Песчаный за Амурским заливом.
- `public/geo/complexes.json` — точки и контуры ЖК.
- `lib/fixtures/bills.ts` — 3 образцовые квитанции демо-дома `fregat-2-1` (54,2 м², двое жильцов) по реальным тарифам Владивостока до и после индексации 1.10.2026, глоссарий строк.
- `lib/fixtures/documents.ts` — реальные городские работы и отключения осени 2026 (источник и дата в каждом тексте) и пересказы к ним для mock-ИИ.
- `public/demo/pothole.svg` — «пример фото» для мастера жалобы.
- `scripts/fetch-*.mjs` — скрипты обновления этих данных (`npm run fetch-geo`, `npm run fetch-buildings`). `fetch-geo.mjs` перед записью границ отрезает части районов западнее 131.8° (функция `mainland()`) для любого источника.

### 3.2 Схема Prisma (SQLite)
- `District(id, name, population, populationYear, color)`
- `Microdistrict(id, name, districtId, lat, lng)`
- `Complex(id, name, developer?, street?, status, floors? (строка), note?, microdistrictId, lat, lng)`
- `ManagementCompany(id, name, rating, avgResponseDays, isDemo=true)`
- `Building(id, address, lat, lng, floors Int?, yearBuilt?, wallMaterial?, apartments?, complexId?, microdistrictId, managementCompanyId?, lastCapRepairYear?, nextCapRepair?, isDemo=true)` — у новостроек этажность может быть неизвестна.
- `Issue(id cuid, buildingId?, lat, lng, category, title, description, photoUrl?, authorityId, appealText, status="new", severity=2, supports=0, createdAt)`
- `Authority(id, name, handles (JSON-строка), contact?)`
- `Bill(id, buildingId, period "YYYY-MM", items (JSON), total)`
- `CityWork(id, title, sourceText, plainSummary, kind, startDate, endDate?, lat?, lng?)` + `CityWorkImpact(workId, buildingId)` (составной PK)
- `User(id cuid, email? unique, passwordHash?, name, phone?, esiaId? unique, verified=false, createdAt)`, `Session(id, userId, expiresAt, createdAt)` (каскадное удаление), `CabinetData(userId PK, json, updatedAt)` (каскадное удаление).

Справочники (`lib/types.ts`):
- категории `road, lighting, entrance, flooding, garbage, elevator, roof, yard, water, noise, other` → «Дорога, Освещение, Подъезд, Подтопление, Мусор, Лифт, Крыша, Двор, Вода, Шум, Другое»;
- статусы `new, sent, in_progress, resolved` → «Новая, Отправлена, В работе, Решена»;
- виды работ `road, improvement, utility_outage, cap_repair, construction, other` → «Ремонт дороги, Благоустройство, Отключение, Капремонт, Стройка, Другое»;
- severity 1 | 2 | 3.

### 3.3 Сид (`prisma/seed.ts`, детерминированный: свой PRNG от строки-соли)
- Районы, микрорайоны, ЖК — из `vladivostok_seed.json`. Район микрорайона — реальная граница, содержащая его центр; центр вне всех границ — микрорайон не создаётся. Маркер микрорайона — середина его реальных домов.
- ЖК ставится по OSM-контуру или точному адресу. Дома ЖК — реальные здания внутри контура (`osm-complex-buildings.json`); этажность из OSM, иначе — этажность ЖК, если она одна. Если внутри контура зданий нет, но у ЖК есть адрес — один дом на его адресной точке (так у ЖК «Легенда», ул. Гамарника, 18б). ЖК без контура и без адреса не создаётся.
- Обычные дома — ближайшие реальные дома OSM к центру микрорайона внутри того же района.
- УК — 8 вымышленных (`isDemo`) с рейтингом и скоростью реакции.
- Жалобы (~105) — на реальных домах, все привязаны к дому, распределены неравномерно с горячими точками: подтопления — Вторая Речка, ямы — Нейбута, свет — Чуркин, мусор — Патрокл. **Демо-дом `fregat-2-1`: ровно 3 открытые и 1 решённая.**
- Работы — из `lib/fixtures/documents.ts`, дома — по адресам из текста (как в 6.1, `summarizeDocument`).
- Квитанции — 3 штуки из `lib/fixtures/bills.ts`.
- `npm run setup` = `prisma db push && node scripts/fetch-geo.mjs && prisma db seed` (fetch-geo по умолчанию берёт готовые границы, `--refresh` — скачивает заново).

- `lib/db.ts` — Prisma-синглтон.
- `lib/queries.ts` — серверные запросы к БД, отдают DTO из `lib/types.ts` (JSON-поля распарсены, даты в ISO): `getDistricts`, `getDistrict`, `getComplex`, `getBuilding`, `getIssues`, `getCityWorks`, `getAuthorities`, `getDistrictStats`.

## 5. Экраны

### 5.1 Раскладка
- **Десктоп (≥ 768 px):** слева вертикальный рейл 88 px: Карта, Поиск, Слои; разделитель; Проблема, Квитанция, Работы; внизу Кабинет и круглая кнопка темы. Карта — всё справа от рейла. Панель — слева поверх карты, 420 px.
- **Телефон:** нижний таб-бар из 5 пунктов (Карта, Проблема, Квитанция, Работы, Кабинет); тема и «Слои» — круглые кнопки справа сверху на карте; панель — нижняя шторка с тремя положениями (свёрнута — 112 px, половина, почти весь экран — отступ сверху 64 px), тянется за ручку. На уровне города шторка свёрнута.
- Сверху слева над картой — **поиск** (колонка 384 px) и под ним ряд чипов: **крошки** и **«Мой дом»** (сердце; ведёт на сохранённый дом или в кабинет, если домов несколько; скрыт, если сохранённых домов нет или вы уже на этом доме). Левые края поиска и чипов совпадают. Крошки показываются, начиная с района: «Владивосток › Район › … » со ссылками; на уровне города их нет.
- Ссылки рейла и кабинета — `<Link prefetch>` (полная предзагрузка), чтобы разделы открывались мгновенно. Для показа используется production-сборка: `npm run preview` = `next build && next start`.

### 5.2 Карта 2GIS (`components/map/MapView.tsx`)
- Старт: центр `[131.93, 43.12]`, zoom 10, min 8, max 18. Стили: светлый `c080bb6a-8134-4993-93a1-5b4d8c36a59b`, тёмный `e05ac437-fcc2-4845-ad74-b1de9ce07555`.
- Наклон камеры: город 0°, район 35°, ЖК 55°, дом 60°. Перелёт к точке 1400 мс, к району (`fitBounds`) 1200 мс. Отступы камеры учитывают панель и рейл (снизу 40 px).
- **Районы** — полигоны своего цвета: заливка alpha 0.34 в светлой теме и 0.2 в тёмной, обводка в светлой на 1 px толще. В режиме района остальные приглушены (0.06), текущий — 0.6. Подпись района и рамка камеры — по части мультиполигона, где больше всего ЖК и жалоб (иначе по самой большой): `buildShapes`.
- **Наведение на район** не перестраивает полигоны: поверх — отдельный неинтерактивный полигон-подсветка (zIndex 1, alpha +0.24 / +0.23, в режиме района 0.3). Обновления плашки идут через очередь с батчингом по `requestAnimationFrame`; JSX маркеров мемоизирован, так что наведение перерисовывает только плашку. Быстрое движение мыши над районами не лагает.
- **Маркеры** (HtmlMarker через портал React):
  - ЖК — иконка здания;
  - проблемы — коралловые точки 12 px; если точки ближе 48 px на экране — кластер с числом, клик приближает;
  - работы — жёлтые круги с иконкой стройки, только незавершённые и с координатами; в режиме района — только внутри района;
  - дома текущей сцены — чёрные точки, активный крупнее.
  Все появляются с `fade-in zoom-in-50`.
- **Выбранный дом** подсвечивается встроенным выделением здания 2GIS в его точке (с кэшем по точке).
- **Клики:** район → `/d/<id>`; ЖК → страница ЖК; дом → паспорт; **проблема → паспорт её дома с подсветкой этой проблемы** (`issueHref`), а если дома нет — закреплённая плашка; **работа → `/changes?work=<id>`**.
- **Плашки при наведении** (`MapTip`): одна карточка, плавно переезжает между целями (framer-motion, scale 0.94→1, 160 мс); у верхнего края (y < 240) открывается вниз. Содержимое:
  - район — население, ЖК, открытые проблемы;
  - кластер — число и частые категории, «Нажмите, чтобы приблизить»;
  - проблема — категория, заголовок, адрес, статус · дата;
  - работа — вид · даты, заголовок, пересказ (до 4 строк);
  - ЖК — название, улица, статус · этажность, застройщик, домов · проблем.
- **Слои** — popover «Что показать на карте»: ЖК · Проблемы · Работы. Каждая строка на всю ширину плашки, без рамок, с серой заливкой (`bg-muted`); при наведении светлее; включённый слой ещё светлее, полужирный, справа галочка (появляется с анимацией). Popover открывается и закрывается за 200 мс (fade + zoom).
- **Мгновенная смена темы:** `setStyleById` у 2GIS каждый раз скачивает стиль заново, поэтому стили кэшируются в памяти обёрткой над `window.fetch` для `https://styles.api.2gis.com/styles/` (ставится до создания карты; стиль другой темы предзагружается после первого простоя). Кнопка темы шлёт событие `theme:switch`, карта кладёт промис смены стиля в `waits`; кнопка ждёт `Promise.race([Promise.all(waits), 400 мс])` и делает круговое раскрытие через View Transitions API.
- После первой отрисовки карта шлёт событие `map:ready` на `window` (его ждёт заставка).

### 5.3 Панели

Пустые состояния: «Открытых проблем нет.», «Новых ЖК в базе нет — дом можно найти через поиск.»
- **ЖК** (`ComplexCard`): статус-бейдж, застройщик, этажность, список домов (`BuildingLink`; неизвестная этажность не показывается).
- Группы контента в панелях — утилита `panel-box`: скругление 1rem, фон `card`, тень-обводка `0 0 0 1px var(--border), 0 1px 2px rgb(0 0 0 / 0.05)`, padding 1rem.

### 5.4 Паспорт дома (`/house/[id]`)
- Шапка: адрес, крошки, кнопки «Сохранить дом» (сердце) и «Поделиться».
- **Здоровье дома** — кольцо 0–100 с расшифровкой (6.5).
- Блоки (`Section` в `panel-box`):
  - **О доме**;
  - **Управляющая компания** — ссылка на ГИС ЖКХ по адресу;
  - **Капремонт** — ссылка на Фонд капремонта Приморья;
  - **Проблемы** — список открытых: точка, заголовок, категория · статус-бейдж · «N дней назад», кнопка «Меня тоже касается» / «Вы поддержали · N»; под списком — число решённых. С `?issue=` выбранная строка подсвечена (`rounded-xl bg-coral/10 px-3 ring-1 ring-coral/40`, внутри блока) и прокручена к центру компонентом `Spotlight` (`scrollIntoView` после кадра);
  - **Что меняется рядом** — «Подробнее» ведёт на `/changes?building=`;
  - **Квитанции**.
- Кнопки действий: «Сообщить о проблеме», «Разобрать квитанцию» (outline).

### 5.5 `/report` — мастер из 4 шагов
Шаги «Фото → Описание → Адрес → Результат» с прогресс-баром:
1. фото — загрузка или «Пример фото» (`pothole.svg`);
2. описание;
3. адрес — из паспорта, поиском или точкой на карте;
4. результат ИИ — категория, ответственный орган (только из справочника), готовый текст обращения; кнопки «Скопировать», «Открыть Госуслуги „Решаем вместе“», «Сохранить на карте».

После сохранения жалоба сразу появляется на карте (событие `issues:changed`) и в кабинете. Черновик хранится в кабинете.

### 5.6 `/bill` — квитанция
Загрузка фото, PDF или текста, либо «Пример квитанции» → таблица строк с простыми названиями и пояснениями → график по месяцам (recharts) → карточки «что изменилось и что делать». Пример: рост после индексации 1.10.2026 — вода +14 %, водоотведение +17 %, отопление с октября. Разбор можно сохранить в кабинет.

### 5.7 `/changes` — городские работы
- Группы: «Идут сейчас» (пульсирующая жёлтая точка), «Скоро начнутся», «Завершены» (свёрнуто в `<details>`, раскрывается плавно). Работа считается завершённой со следующего дня после `endDate` (даты хранятся в полдень).
- Карточка: вид работ; «Касается вашего дома» (при `?building=`); заголовок; даты; пересказ; «Затронуто домов: N» с первыми 4 ссылками и «и другие»; «Исходный текст» в плавно раскрывающемся блоке.
- **Поиск по улице** над лентой: поле «Улица, например Посьетская» с иконкой лупы и кнопкой очистки. При вводе под полем — чипы-подсказки улиц, где есть работы (до 8, клик выбирает улицу). Лента фильтруется: работа подходит, если среди её улиц (6.4) есть совпадение с запросом или запрос встречается в её тексте или адресах. Под полем — «Найдено работ: N» или «На этой улице работ не объявлено.».
- `?work=<id>` — карточка подсвечена (`bg-work/10 ring-2 ring-work`), прокручена к центру, её свёрнутая группа раскрыта.
- Ниже — «Разобрать свой документ» (`DocumentParser`): вставить текст объявления и получить пересказ.

### 5.8 Кабинет `/me`
- **Не вошёл** — карточка «Вход в кабинет»:
  - кнопка «Войти через Госуслуги» (демо, своя нейтральная стилизация, без брендинга Госуслуг);
  - разделитель «или по почте»;
  - переключатель Вход / Регистрация (плашка переезжает через `layoutId`); поле имени появляется анимированно;
  - почта, пароль (показать/скрыть, не короче 8 символов при регистрации);
  - подпись о том, какие данные хранятся.
- **Вошёл** — карточка профиля: инициалы, имя, бейдж «Подтверждён через Госуслуги» / «Не подтверждён», почта, кнопка выхода.
- Разделы — **списком справа** (sticky, `panel-box`, заголовок «Разделы»): активный пункт — тёмная плашка с `layoutId="cabinet-tab"`, иконки в квадратах, счётчики; у активного пункта нет кольца фокуса после клика (Safari показывает его на кликнутой вкладке), у остальных фокус с клавиатуры виден. На телефоне — ряд чипов. Разделы:
  1. **Мои дома** — сохранённые дома со сводкой, «Что меняется у моих домов», убрать из моих домов.
  2. **Обращения** — мои жалобы и черновик.
  3. **Квитанции** — мои квитанции, сравнение с соседями, взносы на капремонт.
  4. **Счётчики** — внести показание (холодная вода, горячая вода, электричество), история.
  5. **Соседи** — «Доска дома» (объявления) и «Опрос дома» («Ставим шлагбаум на въезде во двор?»); без сохранённого дома — «Сначала сохраните свой дом».
  6. **Настройки** — внешний вид (размер шрифта 1 / 1.125 / 1.25), уведомления (почта, Telegram, о работах, о проблемах, день подачи показаний), профиль, Госуслуги (привязать / отвязать — демо), пароль, удалить аккаунт (с подтверждением).
- **Данные кабинета** (`lib/cabinet.ts`): `{ houses, subscriptions, issues, supported, bills, meters, posts, votes, draft, settings }` в `localStorage`; после входа синхронизируются с сервером (`/api/cabinet/data`) через `mergeCabinets(server, local)` — объединение без потерь, покрыто самопроверкой.
- **Аутентификация** (`lib/auth.ts`, без внешних зависимостей): пароли — `scrypt` (`scrypt$<salt>$<hash>`, сравнение `timingSafeEqual`); сессия — случайный токен в httpOnly-cookie `vdk_session` на 30 дней (`sameSite: lax`, `secure` в production), в БД хранится только SHA-256 токена; не больше 5 попыток в минуту с одного IP; zod-валидация почты, пароля и имени.

### 5.9 Поиск (`components/search/SearchBox.tsx`)

- Плейсхолдер «Найти: …» с примерами, сменяющимися каждые 2,8 с (сдвиг + размытие): «ЖК «Фрегат»», «ул. Нейбута», «Первомайский район», «Босфорский парк».
- Результаты — карточка под полем с абсолютным позиционированием (не сдвигает чипы под поиском). Появляется со сдвигом, пункты — с задержкой 25 мс каждый. В пункте: иконка в квадрате, название, подпись, чип типа (Район / ЖК / Дом). Во время загрузки — скелетоны. Пустое состояние: «Ничего не нашлось. Попробуйте улицу, номер дома или название ЖК.». ## 6. Логика

### 6.1 ИИ (`lib/ai/`, zod, структурированный JSON)
- `classifyIssue({ text, address, photo? })` → `{ category, title, severity, authorityId, reasoning, appealText }`. Ответственный — только из справочника. Обращение — официально-деловое, без выдуманных статей законов.
- `parseBill({ buildingId?, image?, text?, demo? })` → строки с `plainName` и `explanation`, итог, сравнение с прошлыми квитанциями дома: `changes: [{ item, deltaPercent, likelyReason, action }]`.
- `summarizeDocument(text)` → `{ title, plainSummary, what, where[], when, whoAffected, kind }` + привязка `where` к домам (стемы улиц и диапазоны номеров, `houseNumbers`).
- `districtDigest(id)` → 3–4 предложения по статистике района.
- Провайдер: `AI_PROVIDER=mock` (по умолчанию; детерминированный, в демо неотличим от настоящего) или `openai` (`AI_BASE_URL`, `AI_API_KEY`, `AI_MODEL`, `AI_VISION_MODEL`; OpenRouter, GigaChat или YandexGPT через прокси). Невалидный ответ — один повтор, затем mock.

### 6.2 Поиск: `searchAll(q, limit = 400)`
- Все слова запроса должны встретиться в любом порядке (через `norm`).
- Порядок: районы → ЖК → дома из БД → адресные точки OSM, которых нет в БД (одинаковые адреса OSM схлопываются).
- Дома сортируются `Intl.Collator("ru")` по улице и `{ numeric: true }` по номеру; коллаторы и нормализованный индекс точек создаются один раз.
- Район для точки вычисляется только для возвращаемых результатов. Цель: запрос из одной буквы — не дольше ~30 мс на сервере.
- Лимит 400 отмечен комментарием `shortcut:` — короткий запрос не отдаёт весь город, а одна улица никогда до него не доходит.

### 6.3 Паспорт для дома из OSM
`/house/osm-<osmId>`: если такого дома нет в БД — найти адресную точку; если адрес совпадает с существующим домом, открыть его; иначе `upsert` нового `Building` (район — по точке, микрорайон — ближайший в том же районе, `isDemo: false`).

### 6.4 Улицы работ: `getWorkStreets(works)` и `streetPattern(street)`
- Для каждой улицы города — регулярное выражение по её главному слову: самое длинное слово названия без текста в скобках и без стоп-слов (адмирала, генерала, маршала, капитана, академика, лейтенанта, героя, владивостока, летия, первая, вторая, третья, новая, старая). Слово короче 4 букв — шаблона нет.
- Окончания: слово на «-ая» → `ая|ой|ую`; на «-ий / -ый / -ой» → `ий|ый|ой|ого|ому|ом`; иначе — слово целиком.
- Совпадение только с начала слова и до его конца. Ищется в заголовке, пересказе, исходном тексте и адресах затронутых домов.
- Самопроверка `lib/streets.test.ts`:
  - находит «на Посьетской», «по Океанскому проспекту», «ул. Руднева»;
  - не находит «Приморская» в «Приморский водоканал», «Невская» в «Рудневского», «Русская» в «Белорусской», «Адмирала Фокина» в «Адмирала Невельского», «Первая» в «Первой Речки»;
  - для «ул. 5-й» возвращает `null`;
  - падает, если убрать проверку начала слова.

### 6.5 Здоровье дома: `computeHealth`
- 100 минус штрафы:
  - за каждую открытую жалобу — вес по серьёзности (1 → 6, 2 → 10, 3 → 15) и ещё тот же вес × (дней открыта / 90, не больше 1);
  - за возраст дома — первые 5 лет без штрафа, затем 0,4 балла в год, максимум 20; год неизвестен — без штрафа.
- Уровни: ≥ 80 «Всё хорошо», ≥ 50 «Есть проблемы», иначе «Нужно внимание». Расшифровка — по частям («2 открытые жалобы», «Жалобы долго не решают», «Дому 48 лет»).

## 7. Дизайн

- **Минималистичный монохром:** почти белые и почти чёрные поверхности, один цвет «чернил», единственный тёплый акцент — коралловый, только для проблем; жёлтый — работы; бирюзовый — подтверждения. Цвета районов — из `vladivostok_seed.json` (Советский — `#DB2777`).

## 9. Демо-сценарий (проходит без ключа ИИ)

1. Открываю сайт → заставка → карта с 5 районами → наведение показывает плашку → клик по **Ленинскому**.
2. Камера наклоняется к району, слева паспорт района → **ЖК «Фрегат-2»** → дом.
3. Паспорт: этажность из OSM, ссылки на ГИС ЖКХ и Фонд капремонта, 3 открытые жалобы, здоровье дома.
4. «Сообщить о проблеме» → «Пример фото» → ИИ: «Дорога», администрация города, текст обращения → «Сохранить на карте» → точка на карте.
5. «Разобрать квитанцию» → «Пример квитанции» → строки, график, карточки роста после 1 октября 2026.
6. «Работы» → поиск «Посьетск» → авария на теплотрассе. Клик по жёлтому маркеру на карте открывает и подсвечивает работу.
7. Клик по коралловой точке на карте → паспорт её дома с подсвеченной проблемой.
8. Назад к городу → «Слои» → «Проблемы» → скопление подтоплений на Второй Речке.
9. Кабинет → регистрация → сохранённый дом → чип «Мой дом» под поиском.

## 12. Чего не делать

- Не подключать реальные городские системы и не отправлять обращения по-настоящему.
- Не выдумывать реальные факты: телефоны, адреса органов, номера законов, УК и годы постройки реальных домов.
- Не использовать брендинг Госуслуг: вход через Госуслуги — демо.
